# TeamLink 导出共创画布

目标：修改眼前的作品，立即看到界面、请求、错误、重试和文件的连带变化。用户不必先确认需求、换角色或提交交付，才能体验作品。

主稿为 `canvas-v2.svg`（1440 × 1000），预览为 `canvas-v2.png`。SVG 保留独立文字和矢量形状；PNG 已渲染并检查。未调用新的 Figma 工具，未修改应用代码。

## 核心对象

左侧大区是一件可以直接操作的导出产品：标题、说明、错误提示和按钮文字就地编辑；月份与分类是真实筛选；导出和重试使用当前数据生成浏览器内样例文件。右侧只保留三条与作品紧密相关的规则：失败是否保留筛选、重试沿用首次还是眼前条件、等待几秒超时。

规则与数据一变，下面四段过程同时重算：首次请求 → 超时 → 再次请求 → 文件。它们是同一个过程的因果轨迹，不是必须逐步通过的流程导航。未实际执行的推演应标明为“演算”，不能伪称调用过服务或检查过代码。

## 直接反馈

| 修改 | 马上可见的结果 |
| --- | --- |
| 改标题、说明、错误或按钮文字 | 当前作品原位更新，不经过生成按钮 |
| 切换失败后保留筛选 | 超时后的筛选值、重试参数和文件范围一起变化 |
| 切换首次条件／眼前条件 | 超时后再改分类时，轨迹显示重试到底采用哪一组参数 |
| 拖动超时秒数 | 同一次操作的超时节点和提示时间同步变化 |
| 改表格日期、分类或内容 | 命中行数、请求范围和下载数据同步变化 |
| 保留对照 | 冻结当时的作品、规则、数据和结果；之后的修改只影响当前版 |

稿中当前选择为 2026 年 10 月／产品，4 条数据中命中 2 条。当前规则保留筛选，因此重试拿到 2 条；已保留对照在超时后清空筛选，因此重试带回 4 条。这些数量应从数据演算，不能把红绿结果写死。

## 布局与移动端

桌面以作品为主，规则紧邻，四段结果完整铺开，数据表就在下方。顶部只有撤销、重做、保留对照和分享；不放向导、角色切换或大幅营销内容。沿用暖白 `#F7F6F2`、墨蓝 `#172D3B`、青绿 `#176D67`。

手机先显示作品。选择对象后，相关规则在附近展开；编辑时保留一条可见的结果摘要，例如“当前重试：10 月／产品 · 2 条”。完整轨迹与数据表可继续下滑查看，不能让每次改动都需要滚到另一屏才能找到反馈。对照按相同节点上下排列，不缩成难读的两列微型文字。

所有人物及数据均为虚构。固定演算假设在规则区小字说明，不用假角色或自动生成叙事代替实际反馈。
