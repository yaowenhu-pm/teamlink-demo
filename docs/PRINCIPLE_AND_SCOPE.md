# 导出即时共创画布：原则与范围

用户希望任何访客打开网页便能直观修改内容，让正在创造的东西即时响应，从中理解、尝试并产生新想法。本版选择一个可直接塑造的数据导出小应用作为完整起点：编辑、运行过程和结果同时可见。

## 设计原则

从 Bret Victor 的三份原始资料中采用以下原则：

| 原始资料 | 本版如何应用 |
| --- | --- |
| [Learnable Programming](https://worrydream.com/LearnableProgramming/)：看见执行、状态，并从具体作品继续塑造 | 展示导出的过程与中间状态；拖动时间线便能查看某一时刻，编辑后重新计算整条轨迹。 |
| [Explorable Explanations](https://worrydream.com/ExplorableExplanations/)：解释与可探索的例子结合，公开影响结果的模型 | 每个参数有明确含义；同时呈现规则、结果和相关说明，让访客能验证自己的猜想。 |
| [Scrubbing Calculator](https://worrydream.com/ScrubbingCalculator/)：就地改变数值，让关联位置共同响应 | 直接编辑作品中的文案、数据和参数；同一个值驱动所有关联情境中的实际表现。 |

## 本版范围

- **直接编辑**：就地修改界面文案和示例数据；行为参数实际决定导出、超时、重试及条件保留等结果，所有情境使用同一套规则。
- **观察与尝试**：可操作导出小应用，查看并拖动执行时间线；在具体示例上修改，观察结果与原因的变化。
- **比较与回退**：冻结基线，与当前方案在同一输入下比较；支持撤销和重做，便于尝试不同想法。
- **带走与接续**：下载当前数据对应的 CSV、导出当前方案的规格，并生成携带作品快照的分享链接。

行为由明确、确定的浏览器规则产生。本版不调用实时 LLM，不根据任意提示词生成应用，也不执行访客提交的代码。需求规格是作品当前状态的表达，不代表真实研发、部署或人工验收已经完成。

## 数据与验收边界

每位访客编辑自己的浏览器本地文档。分享链接在 URL 片段中携带快照，接收者打开的是可继续修改的副本；后续修改不会自动同步给原作者。本版不宣称真实多人共同编辑同一份文档。

使用虚构、隔离的示例数据，不接入私人团队服务、企业账号、飞书或 GitHub 写入。访客输入不提交到业务后端；主动分享时，链接接收者可以读取快照内容。

已完成模型自动检查，以及桌面与390像素手机尺寸浏览器的编辑、对比、撤销、文件和分享恢复核验。线上入口在本版发布后单独核对；具体已观察结果见[VERIFICATION.md](VERIFICATION.md)，不把范围文档当作功能证明。


## 2026-10-31 · 围绕成果的异步协作

借鉴 GatherThread 把项目语境、文件、版本和显式 Agent 请求并置的方式。TeamLink 的中心仍是直接可编辑的作品；规则→行为→文件沿用同一模型即时计算。工作区增加命名方案、关联快照批注和外部 Agent 提案审阅；版本冲突通过完整规范化文档比较拦截，短版本标识仅用于展示。

当前定义为副本协作：没有在线共享状态或身份认证。公开演示不借在线头像、假 Agent 输出或固定模板切换来暗示这些能力。项目包是在现有飞书／GitHub渠道中异步传递上下文的文件；平台自动同步需要后续独立接入。
