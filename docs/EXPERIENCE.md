# TeamLink 使用与交接（历史原型）

以下记录保留旧工作区与需求交接原型。当前公开体验以 [国内共享风景](https://teamlink.yaowenhu.cn/) 和仓库 README 为准。

直接打开 [公开工作区](https://yaowenhu.cn/teamlink-demo/app/)，无需账号。修改留在本浏览器；公开默认内容为虚构示例。

## 修改作品

“作品与规则”里，虚线文字可直接修改；开关、重试来源、超时预算控制实际计算。顶部显示选择→请求→文件的关系，下方显示同一规则算出的最终文件。原型中的试运行可查看过程，只有成功状态可以下载“这一步”的文件；“下载计算结果”始终对应完整计算终态。

“数据与文件”可修改日期、分类、内容、金额，增加或删除记录，并查看完整输出。“验证与过程”可来回查看执行状态，切换耗时情境，修改期望。假设和期望均可调整，不能当成真实网络测试或团队验收结论。

## 留下可继续工作的版本

在协作区填写项目名称、目标和本地署名。命名方案保存完整快照，后续编辑不会改变它。选择版本作对照，会在验证轨迹中显示当时的选择、请求与文件；恢复某版会替换当前作品，可以撤销。

批注需要选择关联位置，保存时连同当时作品一起冻结。定位关联处查看当前作品；对照当时版本可核对问题发生时的状态。批注和署名只在本地记录，不会发送给其他人。

## 交给自己的 Agent

1. 在“Agent 交接”写下具体目标并选择关联位置。
2. 复制任务内容到自己的 Codex，或下载 JSON 后让它读取。任务含项目目标、完整基准作品、相关批注和返回格式。
3. Codex 在外部执行，返回一个 `teamlink-proposal` JSON。提案只能修改明确支持的文案、数据、筛选、规则、网络假设和期望；网页不执行返回的代码。
4. 粘贴或导入 JSON，先看字段变化与结果差异。这里的结果来自本地计算，提案里的理由是作者陈述。
5. 核对后采纳；可以撤销。当前作品与基准不一致时会阻止采纳，不自动合并；重新导出当前版本委托，或自行选择需要保留的改动。

网页没有替你调用大模型，不会显示虚构执行进度。署名和提案来源由使用者核对，不能作为成员身份认证。

## 交给同事

“分享作品”链接携带当前文案、规则与数据，收到的人改自己的副本，不覆盖原作者。二维码打开默认起点，不包含你的修改。

“导出项目”还包含项目目标、命名方案、关联批注和本地活动。你可以自行把文件放进飞书或 GitHub；收件人在“导入项目”选择该文件，继续试验和交接。导入会替换当前项目上下文，建议先导出备份。仅“导出作品 JSON”不携带批注和方案。

当前不提供同一房间实时同步、自动合并、线上成员权限或飞书／GitHub自动写入。浏览器存储也可能因清理或容量限制失效，重要版本请导出留存。


## 官网入口与旧分享

[官网](https://yaowenhu.cn/teamlink-demo/)提供可修改的产品片段。点击“带着这一版，继续改”后，标题和规则会随链接带入独立工作区副本；直接点“打开工作区”则恢复本浏览器已有的普通作品。官网片段本身不写入本地存档。

历史根路径的 `#doc=` 链接会自动保留查询参数和作品内容，跳转至 `app/`。默认工作区二维码也进入 `app/`，不包含官网片段的修改。原官网二维码保持根路径入口。共享副本的项目记录使用稳定的本标签页存储键，改作品后刷新仍可恢复相应方案与批注。
